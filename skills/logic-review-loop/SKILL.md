# Logic Review Loop

## 目标
建立可重复的“逻辑推演 -> 问题修复 -> 再推演”闭环，直到无未解决问题。

## 触发时机
- 任何跨工程需求。
- 单工程但有复杂调用链、状态机、异步事件、补偿逻辑。
- 用户明确要求“多轮推演修复”。

## 循环步骤（必须按序）
1. 建立当前轮推演范围：主工程 + 依赖工程 + 关键链路。
2. 逻辑推演（大范围）：
   - 主路径闭环。
   - 异常路径可达。
   - 回滚/补偿路径可执行。
   - 契约兼容（字段、状态码、事件）。
   - 并发/重复请求防重策略。
3. 记录问题：
   - 主工程：`03-changes.md`
   - 主工程过程日志：`process/round-<N>.md`
   - 依赖工程：`01-change-points.md`
   - 每条问题必须有“影响范围、根因、修复方案、验证方式、状态”。
4. 实施最小修复。
5. 复验并进入下一轮推演。

## 退出条件
- 所有问题状态为 `closed`。
- 最新一轮无新增问题。
- 回归验证通过。

## 提交前门禁
- 所有工程的推演记录已同步。
- 所有工程都完成提交并可追溯到同一 `requirement_key`。
