# 技术方案文档格式

> **按需加载**：本文件由 doc SKILL.md 在生成技术方案文档时 Read 加载，不随 SKILL.md 一起全量加载。

## 写作约束（强制，优先级高于模板本身）

模板结构不变，但**按以下约束填写，不涉及的章节整节删掉，不留占位符、不写无用内容**：

| 约束 | 要求 |
|---|---|
| **背景/目标简短** | 项目背景 + 目标各 1-3 句话说清「为什么做 + 做什么」，禁止铺陈、禁止复述需求文档原文 |
| **涉及流程 → 画流程图** | 有分支/状态流转/多步骤的，必须画流程图（ASCII 首选，样例见下），**每条分支线必须标走向条件**，异常/降级分支也要画 |
| **涉及服务交互 → 画泳道图** | 跨服务调用必须画泳道图（ASCII 首选，样例见下），标清调用方向、调用内容、调用时机 |
| **涉及表/Nacos 配置 → 表格写清** | 表字段、配置项一律用表格逐项列出（字段名/类型/默认值/说明），禁止「详见代码」 |
| **涉及接口 → 标明新增/修改** | 每个接口必须写全 `[新增]`/`[修改]` 标记 + 完整 URL + 出入参改动（修改的接口要标出哪些字段是本次新增/变更） |
| **涉及灰度/放量 → 写节奏和配置** | 必须写清放量节奏（分几批、每批比例/范围、观察指标）+ 对应要改的配置项（Nacos dataId + key + 各阶段取值） |
| **其他不写** | 不涉及的章节、无实质内容的章节，**整节删除**；不写「无」「暂无」「待补充」这类占位行 |

### 流程图样例（ASCII，业务流程首选）

```
              ┌────────────────┐
              │ 用户进入充电页  │
              └───────┬────────┘
                      │
                      ▼
            ┌────────────────────┐
            │ 查询用户保分         │
            │ (guan-zhong→大数据)  │
            └─────────┬──────────┘
                      │
            ┌─────────┴──────────┐
            │  保分查询成功？      │
            └─────────┬──────────┘
             成功 │        │ 失败/超时
                  ▼        ▼
      ┌────────────────┐  ┌──────────────────┐
      │ 判断保分是否达标 │  │ 降级：按无保分处理 │
      └───────┬────────┘  │ (不阻断主流程)     │
              │           └─────────┬────────┘
    ┌─────────┴─────────┐           │
    │  保分 >= 阈值(80)？ │           │
    └─────────┬─────────┘           │
        是 │      │ 否               │
           ▼      ▼                  │
   ┌───────────┐ ┌───────────┐       │
   │ 展示权益价 │ │ 展示原价   │<──────┘
   └─────┬─────┘ └─────┬─────┘
         └──────┬──────┘
                ▼
        ┌───────────────┐
        │ 用户下单充电    │
        └───────────────┘
```

要点：判断节点单独成框并写成问句、**每条分支线旁必须标条件**（是/否、成功/失败、状态值）、异常与降级分支必须画出来、汇聚点和终点要明确。

> 分支多到 ASCII 画不下时改用 mermaid `flowchart TD`，分支同样必须带 `|条件|` 标注。

### 泳道图样例（ASCII，跨服务交互首选）

```
┌──────────┐      ┌─────────────┐
│ 大数据服务 │      │   北保服     │
│          │      │             │
└────┬─────┘      └──────┬──────┘
     │ 定期查询保分       │
     │ (直连北保服)       │
     │──────────────────>│
     │                   │ 返回保分数据
     │<──────────────────│
     │                   │
     │ 处理保分数据       │
     │ (365日内退保→保分=0)│
     │                   │
     │ 提供保分查询接口    │  guan-zhong scene=1~5 按需调用
```

要点：服务名放框内、箭头标调用内容、箭头旁括号补充调用方式/条件、右侧注释写调用方与场景。
