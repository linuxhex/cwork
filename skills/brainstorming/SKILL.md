# Brainstorming

## 目标
把模糊需求转成可执行输入，明确主工程与依赖工程的职责边界。

## 必做清单
1. 复述需求目标和验收标准。
2. 列出主工程改动点。
3. 列出每个依赖工程改动点。
4. 列出跨工程调用链和数据/事件影响。
5. 给出风险、回滚点、灰度策略。

## 输出模板
输出到主工程需求目录下的 `01-analysis.md`，至少包含：
- 背景与目标
- 范围内 / 范围外
- 主工程改动点
- 依赖工程改动点
- 关键风险与防护
- 验收标准

## 约束
- 没有明确验收标准时，不得进入 `writing-plans`。
- 有跨工程影响时，必须逐个工程给出改动理由。
