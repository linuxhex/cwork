# 推演收敛检查清单

> **按需加载**：本文件由 implement SKILL.md 在进入推演收敛阶段时 Read 加载，不随 SKILL.md 一起全量加载。

## 业务层面检查（必须，8 项）

| 检查项 | 说明 |
|--------|------|
| 业务流程完整 | 业务主流程是否闭环，所有业务节点是否串联 |
| 业务规则正确 | 业务规则是否正确实现，条件判断是否完整 |
| 业务状态流转 | 状态机是否完整，状态流转是否合法 |
| 业务数据完整 | 业务数据是否完整，关联数据是否一致 |
| 业务权限控制 | 业务权限是否校验，越权场景是否覆盖 |
| 业务边界场景 | 业务边界条件是否覆盖，极端场景是否处理 |
| 业务依赖关系 | 业务依赖是否完整，前置条件是否校验 |
| 业务异常恢复 | 业务异常是否可恢复，补偿机制是否完整 |

## 技术层面检查（必须，6 项）

| 检查项 | 说明 |
|--------|------|
| 主路径闭环 | 正常流程是否完整执行 |
| 异常处理完整 | 超时、失败、重试是否处理 |
| 契约一致 | 跨工程接口字段是否匹配 |
| 边界条件覆盖 | 空数据、大数据量、特殊字符等 |
| 并发防重 | 重复请求是否防重 |
| 数据一致性 | 跨工程数据是否一致 |

## 接口规范检查（必须，3 项）

| 检查项 | 说明 |
|--------|------|
| 参数校验完整 | 入参校验是否完整，必填项是否校验 |
| 返回值规范 | 返回结构是否符合规范，错误码是否完整 |
| 接口幂等性 | 重复调用是否幂等，防重机制是否合理 |

## 稳定性检查（必须，3 项）

| 检查项 | 说明 |
|--------|------|
| 限流熔断 | 是否配置限流熔断，阈值是否合理 |
| 事务一致性 | 事务边界是否正确，回滚是否完整 |
| 缓存一致性 | 缓存更新策略是否正确，失效策略是否合理 |

## 可观测性检查（必须，3 项）

| 检查项 | 说明 |
|--------|------|
| 日志埋点 | 关键节点是否有日志，日志级别是否合理 |
| 配置项完整 | 配置项是否完整，默认值是否合理 |
| 监控埋点 | 关键指标是否有监控，告警是否配置 |

## 前端设计检查（条件触发，仅前端新工程/新页面，4 项）

| 检查项 | 说明 |
|--------|------|
| 设计系统一致 | 色彩/字体/间距是否使用设计 token，无硬编码值 |
| 无障碍基线 | 对比度 ≥ 4.5:1、键盘导航可达、aria 属性完整 |
| 响应式基线 | 移动优先断点、无横向滚动、触控目标 ≥ 44×44px |
| 交互动效合理 | 动画时长 150-300ms、动效传达含义、支持 reduced-motion |

## 过度工程检查（可选，来自 ponytail）

> 审 plan.md / 改动 diff 有没有"能删的复杂度"。只列、不改，改了要用户确认。和上面正确性检查**正交**——这里只盯冗余，不碰正确性/安全。

| 标签 | 含义 |
|------|------|
| `delete` | 死代码 / 没人用的灵活度 / 投机性功能。替换：删掉 |
| `stdlib` | 手写的标准库已有。点名函数 |
| `native` | 依赖或代码在做平台已做的事。点名特性 |
| `yagni` | 只有一个实现的抽象 / 没人改的配置 / 只有一个调用方的层 |
| `shrink` | 同样逻辑更少行。给出更短写法 |

**输出**：每条一行 `L<行>: <标签> <什么>. <替换>.`，结尾 `净: 可 -<N> 行`。无可删：`已精简，放过`。

**代码图谱辅助（可选）**：删之前用 `codegraph impact <符号>` 验证"这段真没人调 / 影响面多大"再决定；未索引跳过。

## 问题分级

| 级别 | 含义 | 处理方式 |
|------|------|---------|
| critical | 影响功能正确性、数据一致性、系统稳定性 | 必须修复，禁止跳过 |
| minor | 影响用户体验、性能优化、历史数据兼容 | 可以暂不修复，但必须记录原因 |

**critical 示例**：主路径不闭环、异常未处理可能导致 NPE、契约不一致、并发数据错乱、数据丢失

**minor 示例**：历史数据格式不兼容（可后续回刷）、性能未优化、边界体验不佳
