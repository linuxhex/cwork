# 前端设计辅助

> **按需加载**：本文件由 implement SKILL.md 在触发前端设计辅助时 Read 加载，不随 SKILL.md 一起全量加载。

## 触发条件

当 plan.md 或需求分析中识别到以下场景时，**必须**触发前端设计辅助：

| 触发场景 | 示例 |
|---------|------|
| 创建全新前端工程 | 新建 React/Vue/Next.js/Nuxt 项目 |
| 创建全新前端页面 | 新增首页、详情页、Dashboard 等 |
| 前端技术栈选型 | 选择 UI 框架、组件库、样式方案 |

**不触发**：修改现有页面局部逻辑、纯后端改动、仅修改样式微调

## 阶段一：设计面试

**每次只问一个问题。每个问题都附上推荐答案。挑战模糊回答。**

禁止接受的模糊词汇：干净、现代、极简、专业、简洁、时尚、直觉。这些词没有意义——追问具体内容。

---

**Q1 — 产品类型**

> "这是什么类型的产品？"

选项：SaaS 应用 / 开发工具 / 消费级应用 / 营销官网 / 内部工具 / 组件库

追问："主要界面是数据看板，还是用户操作流程？"

---

**Q2 — 目标用户**

> "具体描述一个典型用户。"

拒绝："开发者"、"企业用户"、"所有人"。
好答案："5年经验的前端工程师，日常用 Tailwind 和 shadcn/ui，在中型 SaaS 公司工作。"

追问："技术水平如何？是在时间压力下使用还是从容使用？"

---

**Q3 — 品牌个性（5 个形容词）**

> "如果产品是一个人，用 5 个形容词描述它的气质。"

禁用词：干净、现代、极简、专业、简洁、时尚、直觉、用户友好、创新、无缝。
好词：权威、活泼、精确、温暖、沉稳、大胆、坦诚、专注、大胆、安静。

追问："如果这个产品是一本杂志，它是《经济学人》、《Wired》还是设计工作室的作品集？"

---

**Q4 — 情感目标**

> "用户使用产品时应该有什么感觉？不是怎么想——是什么感觉。"

| 感觉 | 设计响应 |
|------|---------|
| 自信 | 零歧义、强 CTA、清晰的空状态 |
| 高效 | 高密度布局、最少装饰、快速交互 |
| 愉悦 | 微动效、有个性的文案、惊喜细节 |
| 平静 | 大量留白、低饱和配色、无紧迫视觉噪音 |
| 强大 | 大字体、大胆色彩、表现力强的交互 |
| 信赖 | 保守配色、精致细节、社会证明 |

---

**Q5 — 视觉参考**

> "说出 3 个你觉得'我们的也要像那样'的产品/网站。不需要同行业。"

对每个参考追问："具体喜欢什么？配色？字体？留白？动效？"

| 参考 | 具体含义 |

**Q6 — 竞品分析**

> "3 个主要竞品？他们的 UI 什么样？你想刻意避免什么？"

追问："要和竞品看起来相似（安全感）还是刻意不同（创新感）？"

---

**Q7 — 色彩方向**（4 个子问题）

- **7a 明暗默认**：亮色（推荐，通用）/ 暗色（开发者/数据工具）
- **7b 冷暖**：冷色（蓝/灰→技术精确）/ 暖色（琥珀/大地→友好亲和）/ 中性（靠主色点缀）
- **7c 单色还是全彩**：单主色+中性灰（精致聚焦）/ 全彩（消费级/高能量）
- **7d 饱和度**：高饱和（活力/创业感）/ 低饱和（成熟/精致/编辑感）

综合输出："冷蓝主色、亮色默认、低饱和、灰色中性色。对应 blue-600 为主色，gray-50 为背景。"

---

**Q8 — 字体方向**（3 个子问题）

- **8a 字体类型**：几何无衬线（Inter/Geist→中性技术）/ 人文无衬线（Nunito/Figtree→友好温暖）/ 衬线（Playfair/Lora→编辑高端）/ 等宽（JetBrains Mono→开发者工具）
- **8b 一种还是两种**：一种字体靠字重变化（连贯现代）/ 两种字体标题+正文（有个性需搭配）
- **8c 信息密度**：宽松（营销/高端，16-18px）/ 均衡（默认，15-16px）/ 密集（看板/工具，13-14px）

---

**Q9 — 组件风格**（4 个轴）

- **圆角**：0px（严肃精确）/ 4px（技术默认）/ 8-12px（友好亲和）/ 全圆/胶囊（活泼消费级）
- **阴影**：扁平无边框（现代极简）/ 微阴影（专业安全）/ 高阴影（传统 SaaS）/ 强阴影（营销页）
- **密度**：宽松 / 均衡 / 密集
- **边框**：粗边框（结构清晰）/ 细边框（标准）/ 无边框（现代极简）

组合速查：密集+粗边框=Bloomberg 终端 / 密集+细边框=Linear/VS Code / 均衡+微阴影=标准 B2B SaaS / 宽松+无边框=高端消费/营销

---

**Q10 — 动效级别**

- **极简**：仅必要反馈（按钮状态、表单错误），无进出动画
- **微妙**：100-200ms 过渡，弹窗淡入，hover 状态（SaaS 推荐）
- **表现力**：列表交错、滚动揭示、弹窗弹性（营销页推荐）
- **强动效**：视差、时间线、滚动叙事（仅营销站）

---

**Q11 — 暗色模式**

- **现在就要**：token 系统必须从一开始就支持双模式
- **以后再加**：用 CSS 变量构建，暗色模式只需覆盖变量
- **不需要**：简化 token 系统

---

**Q12 — 定义性页面**

> "如果有一个页面必须做到绝对完美——定义产品视觉身份的那个页面——是哪个？"

这通常是：首屏/着陆页（第一印象）/ 主看板（用户 80% 时间）/ 产品核心交互页

## 设计准则（编码时遵循）

### Token 系统（三层架构）

**定义顺序**：先定义 token，再在组件中引用。组件禁止直接引用原始值。

**三层结构**：
| 层级 | 命名规则 | 示例 |
|------|---------|------|
| 原始层（Primitive） | `--color-{hue}-{shade}` | `--color-blue-600: #2563eb` |
| 语义层（Semantic） | 按角色命名，禁止按外观命名 | `--color-primary: var(--color-blue-600)` |
| 组件层（Component） | 仅当组件有独特需求时 | `--button-bg: var(--color-primary)` |

**强制规则**：
- **按角色命名，禁止按外观命名**：`--color-primary` 可以在品牌换色时存活，`--color-blue` 不行
- **暗色模式是语义层的试金石**：切换 `.dark` 后颜色正确变化、无需改组件代码，说明 token 设计正确
- **一个含义一个 token**：两个 token 值和含义都相同，必须合并
- **不要 token 化一切**：`border: 1px solid` 中的 `1px` 不需要 token，聚焦于跨主题变化或多次出现的值
- **禁止改变逻辑**：token 替换只改设计值，不改条件、组件结构或功能

**实现要求**：
- 所有颜色、间距、字号、圆角、阴影使用 CSS 变量或 Tailwind token
- 组件内禁止硬编码 hex/rgb/hsl 值
- 暗色模式通过覆盖语义层 token 实现，不改组件代码
- 新增 token 前先检查是否已有同义 token

### 动效准则

**只动 `transform` 和 `opacity`**。如果要动画其他属性（width/height/padding/margin/top/left），停下来，找替代方案。

| 规则 | 说明 |
|------|------|
| 进入用 ease-out | 减速到位，感觉自然 |
| 退出用 ease-in | 加速离开，干脆利落 |
| 进入时长 > 退出时长 | 进入值得关注，退出应该快 |
| 禁止超过 400ms | 滚动揭示可到 600ms，其余不超 400ms |
| 禁止 `linear` 缓动 | 始终用曲线 |
| `prefers-reduced-motion` 必须 | 每个动画都必须尊重用户动效偏好 |

**`prefers-reduced-motion` 模板**（写入全局 CSS）：
```css
@media (prefers-reduced-motion: reduce) {
  * {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
  }
}
```

**一致性**：所有按钮动效一致，所有弹窗动效一致。不要同类组件各有各的动画。

**高度展开（手风琴/折叠）**：用 `max-height` 从 0 到已知最大值，或用 `grid-template-rows: 0fr → 1fr`（纯 CSS，无布局抖动）。

### 无障碍准则

**语义 HTML 优先于 ARIA**：真正的 `<button>` 永远好于 `<div role="button">`。

| 规则 | 说明 |
|------|------|
| 对比度 ≥ 4.5:1 | 正文文本；大文本 ≥ 3:1；UI 组件 ≥ 3:1 |
| 键盘可达 | 所有可交互元素 Tab 键可达，顺序合理 |
| 焦点可见 | 禁止 `outline: none` 除非有自定义焦点样式替代 |
| 颜色不是唯一信号 | 每个仅靠颜色区分的状态变化，必须同时用图标/文字/图案 |
| 图片有 alt | 装饰性图片 `alt=""`，信息性图片写描述 |
| 图标按钮有 aria-label | 无文字按钮必须加 `aria-label` + `<span className="sr-only">` |
| 触控目标 ≥ 44×44px | 增加 padding 而非直接改 width/height |
| 弹窗焦点陷阱 | 打开的弹窗必须锁定焦点，关闭后焦点回到触发元素 |
| 跳过导航链接 | 页面第一个可聚焦元素，指向 `#main-content` |
| aria-live 容器先于内容 | 容器必须在 DOM 中先于内容变化存在 |

**修复优先级**：语义结构 → 交互元素 → 名称标签 → ARIA 正确性 → 对比度 → 焦点可见 → 动效偏好 → 触控目标

**aria-live 模式**：
- 非紧急：`<div aria-live="polite" aria-atomic="true" className="sr-only">{statusMessage ?? ''}</div>`
- 紧急：`<p role="alert">{errorMessage}</p>`
- 需要 aria-live 的场景：toast/通知、表单验证错误、搜索结果数、加载完成提示、实时数据更新

### 文案准则

| 类别 | 规则 | 反例 → 正例 |
|------|------|-------------|
| CTA | 动词开头 + 利益点 | "提交" → "开始免费试用" |
| 错误 | 说清什么错了 + 下一步做什么 | "无效输入" → "邮箱已被注册——试试直接登录" |
| 空状态 | 说明这里可以有什么 + CTA | "暂无数据" → "还没有项目——创建第一个" |
| 占位符 | 给真实示例 | "邮箱地址" → "you@company.com" |
| 加载 | 说清正在发生什么 | "加载中..." → "正在生成报告..." |
| 确认 | 说出操作对象 + 后果 | "确定删除？" → "删除'Q4 报告'？此操作不可撤销。" |
| 标题 | 最强真实主张在前，删所有填充词 | "工作的未来" → "远程工程团队的项目管理" |

**强制规则**：
- 更短永远更好。两个改写同样清晰时，选更短的
- 禁止按钮写"提交"、"确定"、"点击这里"、"继续"（无上下文时）
- 禁止错误信息写"出错了"、"发生未知错误"
- 如果项目用了 i18n 库（i18next/next-intl/react-i18next），所有文案改到翻译文件，不硬编码在组件中
- 同步检查 `aria-label`、`title` 等隐藏文案，它们也遵循同样规则

### 着陆页准则（营销页面）

**首屏优先**：访客看不到首屏价值，其他都不重要。

**5 秒测试**：看首屏 5 秒后能回答以下三个问题，否则首屏有严重问题：
1. 这是什么产品？
2. 给谁用的？
3. 下一步做什么？

**每个视口一个主 CTA**：多个主 CTA 互相抵消。

**正确段落顺序**（像销售论据一样排列）：
1. Hero — 价值主张 + CTA
2. 社会证明 — logo 或数字（紧跟 CTA 之后建立信任）
3. 问题 — "你知道这个痛点"
4. 方案 — "这是更好的方式"
5. 功能 — 具体细节
6. 用户证言 — 有姓名和头像的真实评价
7. 定价 — 在用户认同价值之后
8. FAQ — 处理异议
9. 最终 CTA — 再次收尾

**导航是转化的敌人**：着陆页导航极简，只留 logo + 一个 CTA。每个外链都是流失。

**性能即转化**：
- Hero 图片：`loading="eager"` + `priority`，禁止懒加载
- 字体：`display=swap` + preconnect + preload
- LCP 目标：< 2.5s

**信任信号**：
- 安全："256 位 SSL"、"SOC 2 认证"、"GDPR 合规"
- 保障："30 天退款"、"无需信用卡"
- 评价：星级 + 数量（"4.9 星 · 2,400 条评价"）
- 证言：姓名 + 职位 + 公司 + 照片（匿名证言可信度低 60%）

**OG 图片**：1200×630px，展示产品 UI（不是 logo+纯色背景），缩略图尺寸下文字可读（≥48px 字号）
