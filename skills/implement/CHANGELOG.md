# cwork-implement 变更日志

## [2026-11-09] 高门槛自动改进机制

**触发**：用户要求提高改进门槛，自动执行不需人工介入
**改动**：技能改进自检改为三层检查（门槛检查→自动执行→验证同步记录）
**影响**：只有绝对确定的改进才会自动执行，推测性改进记入 USAGE_NOTES

## [2026-11-09] 新增任务结束自检

**触发**：借鉴 Hermes Agent 自改进机制
**改动**：阶段 6 后加「技能改进自检」章节，任务结束自动输出改进提议
**影响**：每次 implement 结束会提议技能改进

## [2026-11-06] 端到端检查强化

**触发**：实战发现入口到出参链路断裂问题
**改动**：加 HARD GATE 强制端到端验证（入口→改动点→出参/落库完整链路）
**影响**：推演收敛后必须验证完整链路，不能只编译通过就结束

## [2026-11-01] 编码方法论增强

**触发**：借鉴 ponytail/impeccable 思想
**改动**：方案审查加 lazy senior 三问 + 意图优先硬门；编码加最小改动准则
**影响**：审查流程更严格，编码改动更克制

## [2026-10-30] 前端设计增强

**触发**：借鉴 impeccable 设计系统
**改动**：前端检查升级 7 支柱 + critique 评分；DESIGN-BRIEF 模板加产品意图头部
**影响**：新前端工程/页面会触发设计辅助流程

## [2026-10-21] 多服务早期识别

**触发**：实战中识别滞后导致文档重写
**改动**：需求分析阶段开始时主动探测多服务场景
**影响**：避免中途切换模式导致的文档重写
