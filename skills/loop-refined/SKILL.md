# Loop Refined

## 位置与串联
- 仅在 `executing-plans` 阶段内使用。
- 可多轮循环执行。
- 收敛后进入 `commit-code`。

## 阶段目标
- 用系统化逻辑推演发现真实风险。
- 快速修复并复验，直到问题完全关闭。
- 给提交阶段提供高置信度输入。

## HARD GATE
- 任何一轮发现 `open` 问题，禁止退出循环。
- 没有问题记录文件，禁止宣称通过。
- 没有覆盖关键链路（主路径/异常路径/补偿路径），禁止宣称通过。

## 推演覆盖面（每轮最少）
1. 主路径闭环：输入 -> 处理 -> 输出。
2. 异常路径：参数异常、依赖失败、超时、重试。
3. 兼容性：字段、状态码、事件版本。
4. 一致性：跨工程顺序与状态同步。
5. 防重：重复请求、并发触发、重复消费。
6. 回滚补偿：失败后是否可恢复。

## 每轮标准动作
1. 确认本轮范围：涉及工程、模块、链路。
2. 逻辑推演：按覆盖面逐项检查。
3. 记录问题：按模板落到多工程文档。
4. 最小修复：只修当前问题相关代码。
5. 复验：确认问题关闭且无新回归。
6. 触发阶段检查点：同步文档和状态。

## 文档落点（必须）
- 主工程：`03-changes.md`
- 主工程：`process/round-<N>.md`
- 依赖工程：`03-repo-changes.md`

## 问题记录模板（建议）
- 问题编号
- 影响范围（工程/模块/链路）
- 触发条件
- 根因
- 修复方案
- 验证方式
- 状态（open/closed）

## 阶段推进命令

```bash
bash skills/init/scripts/phase_checkpoint.sh \
  --main-dir <主工程绝对路径> \
  --deps <逗号分隔依赖工程绝对路径> \
  --requirement-key <需求key> \
  --phase loop-refined \
  --owner <agent-id>
```

## 退出条件
- 所有问题均为 `closed`。
- 最新一轮无新增问题。
- 回归风险可接受（无阻断级问题）。
- 多工程文档同步完成。

## 与单元测试关系
- 本流程默认替代“新增单元测试作为唯一门禁”。
- 如已有单元测试可执行，可作为辅助证据，但不是硬要求。

## 常见失败与处理
- 失败：同一问题反复出现。
  - 处理：提升到链路级根因排查，不做表层修补。
- 失败：主工程和依赖工程记录不一致。
  - 处理：以主工程总记录为基准，同步修正依赖工程记录。
- 失败：并发修改导致推演结论失效。
  - 处理：加锁重跑本轮推演，更新 round 文档。

## 质量红线
- 不允许“只记录修复，不记录发现过程”。
- 不允许“问题未关闭但标记本轮通过”。
- 不允许“主工程通过、依赖工程未同步”就进入提交。

## 给 commit-code 的交接物
- 问题清单（全 closed）
- 最终改动摘要
- 可提交路径范围
- 最后一轮推演结论
