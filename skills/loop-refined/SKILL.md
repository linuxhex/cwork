# 推演收敛

## 概述

用逻辑推演替代单元测试，自动发现问题并修复。

**核心原则：** 通过逻辑推演验证实现的正确性，而非运行测试。

## 语言约束（强制）

- **所有对话必须使用中文**
- **所有分析必须使用中文**
- **所有结论必须使用中文**
- 仅在必要处保留英文：命令、路径、参数名、状态码、字段名、代码

## HARD GATE

- workflow-state 不是 executing-plans 或 loop-refined，禁止执行
- 未完成计划执行，禁止执行
- **至少执行 2 轮推演才能判定收敛**
- 推演未收敛（仍有未修复问题），禁止进入 commit

## 推演循环

**开始时宣布：** "我正在进入推演收敛阶段，进行逻辑推演检查。"

主 agent 统一推演（跨工程）：

```
round = 1
while round <= 5:
    推演检查：
    - 主路径闭环？
    - 异常处理完整？
    - 契约一致？（跨工程）
    - 边界条件覆盖？
    - 并发防重？
    - 数据一致性？
    
    if 发现问题:
        记录问题到 changes.md
        修复问题
        round += 1
    elif 上轮也无问题:
        break  # 收敛
    else:
        round += 1
```

## 推演覆盖面

| 检查项 | 说明 | 检查方法 |
|--------|------|----------|
| 主路径闭环 | 正常流程是否完整执行 | 逐步骤追踪代码执行路径 |
| 异常处理 | 超时、失败、重试是否处理 | 检查每个外部调用的异常处理 |
| 契约一致 | 跨工程接口字段是否匹配 | 对比请求/响应结构定义 |
| 边界条件 | 空数据、大数据量、特殊字符等 | 分析输入边界和极端情况 |
| 并发防重 | 重复请求是否防重 | 检查幂等性设计和锁机制 |
| 数据一致性 | 跨工程数据是否一致 | 分析数据流转和状态变更 |

## 推演检查详解

### 1. 主路径闭环检查

**目的：** 确保正常流程可以完整执行。

**检查步骤：**
1. 从入口开始，逐步骤追踪代码执行路径
2. 确认每个步骤都有明确的输入和输出
3. 确认路径最终能达到预期终点
4. 记录路径上的所有分支点

**问题示例：**
```
问题：导出流程在获取用户数据后，未处理数据为空的情况
位置：ExportService.java:45
修复：添加空数据检查，返回空文件提示
```

### 2. 异常处理检查

**目的：** 确保所有异常情况都被妥善处理。

**检查步骤：**
1. 列出所有外部调用（API、数据库、文件系统）
2. 检查每个调用是否有异常处理
3. 确认异常处理是否合理（重试、降级、返回错误）
4. 检查异常是否向上传播导致流程中断

**问题示例：**
```
问题：调用 user-service 接口未设置超时时间
位置：ExportService.java:32
修复：添加 5 秒超时配置
```

### 3. 契约一致检查

**目的：** 确保跨工程接口定义一致。

**检查步骤：**
1. 列出所有跨工程调用
2. 对比主工程请求结构和依赖工程期望结构
3. 对比依赖工程响应结构和主工程期望结构
4. 检查字段类型、必填性、默认值

**问题示例：**
```
问题：主工程期望 userId 字段，依赖工程返回的是 user_id
位置：契约定义不一致
修复：统一使用 userId 命名
```

### 4. 边界条件检查

**目的：** 确保极端输入不会导致异常。

**检查步骤：**
1. 列出所有输入参数
2. 分析每个参数的边界值（空、最大、最小、特殊字符）
3. 检查边界值是否有对应处理
4. 检查数据量大的情况是否有分页或流式处理

**问题示例：**
```
问题：导出数据量无上限，可能导致内存溢出
位置：ExportService.java:67
修复：添加最大导出数量限制（10000 条）
```

### 5. 并发防重检查

**目的：** 确保并发请求不会导致数据错误。

**检查步骤：**
1. 列出所有写操作
2. 检查是否有幂等性设计
3. 检查是否有锁机制或去重机制
4. 分析并发场景下的数据一致性

**问题示例：**
```
问题：并发导出同一用户数据，可能产生重复文件
位置：ExportService.java:23
修复：添加导出任务去重锁，基于 userId + exportType
```

### 6. 数据一致性检查

**目的：** 确保跨工程数据流转一致。

**检查步骤：**
1. 列出所有跨工程数据流转
2. 检查数据变更是否同步
3. 检查事务边界是否合理
4. 分析失败回滚机制

**问题示例：**
```
问题：主工程导出成功，但未通知依赖工程更新状态
位置：ExportService.java:89
修复：添加状态同步调用
```

## 推演结论记录

推演结论记录到 `changes.md`：

```markdown
## 推演结论

**轮次：** 3
**收敛状态：** 已收敛

### 发现问题：2 个（已修复）

**问题 1：** 未处理空数据情况
- 位置：ExportService.java:45
- 影响：导出空文件时返回错误
- 修复：添加空数据检查，返回友好提示

**问题 2：** 并发导出未防重
- 位置：ExportService.java:23
- 影响：可能产生重复文件
- 修复：添加导出任务去重锁

### 推演检查结果

| 检查项 | 第1轮 | 第2轮 | 第3轮 |
|--------|-------|-------|-------|
| 主路径闭环 | ✓ | ✓ | ✓ |
| 异常处理 | ✗ | ✓ | ✓ |
| 契约一致 | ✓ | ✓ | ✓ |
| 边界条件 | ✗ | ✓ | ✓ |
| 并发防重 | ✗ | ✗ | ✓ |
| 数据一致性 | ✓ | ✓ | ✓ |
```

## 强制要求

- 至少执行 2 轮推演（round >= 2）才能判定收敛
- 每轮必须检查所有 6 个检查项
- 发现问题必须修复后才能进入下一轮
- 推演结论必须记录到 changes.md
- 连续 2 轮无问题才能判定收敛

## 自动衔接

收敛后自动调起 `cwork-commit` 进行代码提交，不询问用户。
