# 科技速递

## 概述

`cwork-tech-express` 把「三天科技消息」压成一篇可直接发草稿的公众号日更简报：**采集 → 压缩 → 分块 → 评论 → 排版 → 存草稿**。

**核心能力**：
1. **日期锚定** — 用户给日期即以该日为「当日 D」，未给取系统当天；窗口固定 D / D-1 / D-2
2. **三天检索** — 全球并重的媒体清单 + 检索式模板（见 `sources.md`），逐条核实发布时间与原文链接
3. **信息压缩** — 每条压成「标题 + 60-110 字正文 + 一行关系链」，只留名词与数字
4. **分块** — 今日资讯（D 发布）/ 往日回顾（D-1、D-2 发布，带日期徽标）
5. **简要评论** — 条目短评（趋势/发展眼光）+ 文末「速递观察」，覆盖民生/市场/资本/进出口与经济/舆论两个层面
6. **来源可溯** — 每条必带媒体名 + 可访问链接 + 发布日期，禁止编造
7. **排版交付** — HTML + inline CSS（模板见 `template.md`），ImageGen 封面图，用**工作台自带浏览器**（browser-use MCP）写入公众号草稿箱并存草稿

**工作流程**：
```
阶段0 日期锚定 → 阶段1 采集(候选表) → 阶段2 压缩 → 阶段3 分块 → 阶段4 评论 → 阶段5 排版+封面 → 阶段6 写入草稿 → 阶段7 汇报
```

## 语言约束（强制）

全流程对话、分析、结论一律中文；仅命令、路径、参数名、链接、媒体名原文保留。

## 阶段 0：日期锚定（硬约束，先做）

```
D   = 用户给的日期；未给 → 系统当天
D-1 = D 的前一天（往日回顾）
D-2 = D 的前两天（往日回顾）
```

1. 日期归一化：`2026年11月11日` / `2026-11-11` / `11.11` / `昨天` / `前天` 都要先换算成绝对日期。
2. **必须回显窗口并等一句确认**（用户不回复即按默认继续，不反复追问）：
   ```
   窗口锚定：当日 = 2026-11-11（周三），往日 = 11-10、11-09。
   检索范围：全球并重（海外条目约占一半）。回车继续，或直接改日期。
   ```
3. 时区统一按**北京时间**；海外消息按原文发布日期换算，换算后落在 D 才算「今日资讯」。
4. ⚠️ 后续所有检索式必须带**绝对日期**（`2026年11月11日` / `November 11 2026`），禁止用「今天/最新」这类相对词检索——搜索引擎会把旧闻排进来。
5. 产物目录按 D 命名：**`$CONTENT_DIR/tech-express/<YYYYMMDD>/`**（外置内容目录，不在仓库、不入 git）。`$CONTENT_DIR` 按共享规范 `cwork-common/output-dir.md` 解析：用户当轮指定 > 环境变量 `CWORK_CONTENT_DIR` > 仓库根 `cwork.content.json` 的 `contentDir`（当前 = `D:/zzz/articles`）> 兜底 `<repo>/docs/articles`（兜底要告知）。**锚定日期后立即解析一次并回显落点**，本期所有文件只写这一处；目录已存在则视为**更新当期草稿**（复用 appmsgid，不新建草稿）。

## 阶段 1：消息采集

**工具顺序**：`WebSearch`（带时间范围）→ `WebFetch` 打开原文核实发布日期/数字/取正文 → 站点需渲染或需登录时用工作台自带浏览器（browser-use MCP）打开。

**执行节奏**（同一批查询并行发出，不要一条条串行等）：

1. 按 `sources.md` 的**领域 × 语言**矩阵发检索：7 个领域 × 中/英各 1 次起步，至少 14 次查询。
2. 对清单里的「快讯/滚动」页直接 `WebFetch` 拉列表（36氪快讯、IT之家滚动、财联社电报、TechCrunch、The Verge 等）。
3. 候选规模：**25-40 条**起步，最终入选 **今日 5-8 条 + 往日 6-10 条**。
4. 每条候选落盘到 `<目录>/candidates.md`，字段固定：
   ```
   - 事件一句话 | 领域标签 | 媒体名 | 发布日期(核实后) | 链接 | 关键数字 | 核实状态(已开原文/仅搜索快照)
   ```

**硬约束（不可放宽）**：

- **禁止编造**链接、数据、人名、日期。链接只能来自搜索结果或原文页，且 `WebFetch` 打开过才标「已核实」。
- 拿不到原文（付费墙/超时/需登录）→ 只用标题与搜索快照，并在正文写「据 <媒体> <日期> 报道」，**不写成已核实**。
- 发布时间必须核实：只有原文页日期为准；日期分不清落在 D 还是 D-1 的，降级进「往日回顾」或不选。
- 同一事件多媒体转载 → 合并成 1 条，主源 1 个 + 佐证源最多 2 个，链接给主源。
- 排除：纯营销稿、无实质进展的预告、标题党、无法验证的传闻（确属重要则保留并写明「未经证实」）。
- **与上期查重**：若存在上一日目录，用其 `body.html` 的标题关键词 `Grep` 本期候选；往日条目重复则降权或换条目，避免天天同一件事。

**入选排序标准**（四条按权重）：影响面（用户数/金额/国家地区数）＞ 格局改变（竞争关系/供应链/规则）＞ 可验证性（有原文有数字）＞ 读者相关性（钱包、工作、日常使用）。

## 阶段 2：信息压缩

每条压成固定三件套，**一个条目只讲一件事**：

```
标题： ≤20 字，动词开头，说清「谁做了什么」
正文： 60-110 字 —— 核心主题 + 主体与事件的关系（谁 → 做了什么 → 为什么/依据 → 直接影响谁）
关系链：一行 `主体A → 动作 → 受影响方B`（复杂事件必须拆直）
```

压缩原则：
- 删形容词与副词，只留名词、数字、主体名；不复述原文句子。
- 金额、份额、日期、型号、人数必须与原文一致，四舍五入要标「约」。
- 背景补充用括号，≤15 字；正文里不解释行业常识。
- 涉及多方时点明立场（谁受益、谁受损、谁被约束）。

## 阶段 3：分块

| 块 | 内容 | 要求 |
|----|------|------|
| **今日资讯** | 发布日期 = D | 5-8 条，海外至少 2-3 条 |
| **往日回顾** | 发布日期 = D-1、D-2 | 6-10 条，每条前带 `D-1`/`D-2` 日期徽标，海外约占一半 |

- 块内排序：影响力优先，同级按领域聚类。
- **领域标签**（每条恰好 1 个，只作标签不作分块）：`AI·芯片`｜`智能硬件`｜`互联网平台`｜`新能源·智造`｜`出海·跨境`｜`政策·监管`｜`资本·并购`
- 往日回顾不是"次要内容"：只收**仍在发酵**的事（后续影响未落地、有反转、有数据补全），纯补量的旧闻删掉。
- **时区换算会抽空往日块的海外占比**：D-1 美东下午发布的大事，换成北京时间常已落到 D，只能进今日块。此时往日海外不足一半属正常，**不塞旧闻凑占比**，改为在 `candidates.md` 记「已知偏差」并写清成因。
- 候选已被核实但被正文配额挤掉 → **不丢弃**，降格写进速递观察卡当论据，并在 `candidates.md` 该行标「（未单列）… 写入观察卡」，保持台账与成文一一对应。

## 阶段 4：简要评论

### 4.1 条目短评（每条 1 条，≤45 字）

以趋势、发展的眼光点出**最直接影响**，说「意味着什么」，不重复正文事实。范式：
- `两年内 xxx 的成本曲线会被压平，yyy 环节最先承压。`
- `规则落地比表态重要，先看灰度范围，再看罚例。`

### 4.2 文末「速递观察」（2-4 条，每条 80-150 字）

从下表维度中挑**当日真正有依据**的写，不凑齐四维：

| 维度 | 关注点 |
|------|--------|
| 民生 | 就业、消费价格、使用门槛、隐私与安全 |
| 市场 | 竞争格局、供应链、替代关系、渠道 |
| 资本 | 估值与融资节奏、一二级市场情绪、产业资本流向 |
| 进出口 | 关税、出口管制、出海合规、国产替代 |

同时把结论分成两层写清楚：
- **经济层面**：钱和产能往哪走，谁的成本变了，谁的收入结构变了。
- **舆论层面**：争议点是什么，两方各说什么，有无被忽略的第三方代价。

**评论硬约束**：
1. 评论必须能被阶段 1 的事实支撑，无支撑就删掉这段评论。
2. **不构成投资建议**（文末固定声明），禁止预测具体股价、涨跌、买点。
3. 争议事件必须标注各方说法与来源，不站单方。
4. 允许说「信息不足，无法判断」——比硬凑观点好。

## 阶段 5：排版与封面

1. 正文 = **HTML + inline CSS**（公众号编辑器不吃 class）。直接复制 `template.md` 骨架填内容，禁止改结构语义、禁止改成 Markdown 交付。
2. 视觉元素至少 3 种（模板已内置）：日期条 / 领域标签 / 条目卡片 / 短评浅底色块 / 速递观察渐变卡 / 来源灰字行 / 分隔线。
3. 篇幅：正文 CJK 字数 **1500-2200**（`build-inject.cjs` 会打印计数）。确需超上限→ **要用户明确豁免**，并把打印值与理由记进 `candidates.md` 的「定稿口径」，不得静默超标。
4. **封面图强制**：调用 ImageGen 实际生成，`size="2560x1080"`，prompt 见 `template.md`；无文字；存 `<目录>/images/00-cover.png`，再用 `make-cover.ps1` 压成 `00-cover.jpg`（清 ~2MB 限制）。ImageGen **实际返回尺寸常小于请求值**（20261113 请求 2560×1080、实得 1584×672），比例对即用，不为凑尺寸反复重生成。
5. 正文默认**不插图**（简报体裁靠排版而非配图）；用户明确要配图时才按 `［插图 N｜说明 → images/xx.png，插入后删掉本行］` 标记加图，并走 article skill 的正文图上传流程。
6. 标题：`科技速递 · <M月D日>`，可加当日主线（≤64 字）：
   ```
   科技速递 · 11月11日｜AI 芯片与跨境关税同日收紧
   ```

标题与评论口径**先给用户过一眼**（一次给出标题 2-3 选 1 + 速递观察要点），确认后才进阶段 6。

7. **首屏声明行 + 署名（固定动作）**：日期条内除窗口行与「今日主线：…」外，再加一行「本文为公开报道的编辑整理与独立分析，事实均来自标注来源，观点为本号所有。文｜日新」，footer 用笔名收尾。笔名固定 **日新**（已定，不每期换）；为何能声明原创、何时要谨慎（留言/赞赏、新闻资质边界）见 `template.md` 第五节。**「声明原创」开关两条链路都不代点**，列为待手动。

## 阶段 6：写入公众号草稿

**默认走工作台自带浏览器（browser-use MCP）**，不另起 Chrome。逐步工具调用、页内 JS 片段、失败手册全在 [deliver.md](deliver.md)，以下为纲要与铁律。

产物目录 `$CONTENT_DIR/tech-express/<YYYYMMDD>/`（外置内容目录，解析见 `cwork-common/output-dir.md`）：

```
candidates.md      # 阶段 1 落盘（含核实状态）
body.html          # 阶段 5 正文（inline CSS 片段，无 class）
inject-fn.js       # 脚本生成（箭头函数版）—— 自带浏览器 evaluate_script 用这份，勿手改
inject.js          # 脚本生成（IIFE 版）—— 仅备用 Playwright 链路用
images/00-cover.png / 00-cover.jpg
draft-report.json  # 本轮执行与复验结果
```

**步骤**（细节见 deliver.md 路径 A）：

```bash
# 0) 先生成注入体（仓库根目录）
node skills/tech-express/scripts/build-inject.cjs "$CONTENT_DIR/tech-express/<YYYYMMDD>"
```

**步骤 00：先探能力**。调一次 `list_pages`：报 `tool not found`（40404/51404）且同会话另一个无关 MCP 也报错 → 本会话 **MCP 工具未注册**（上下文压缩后续接的会话常见；浏览器面板本身可以是好的），**不要穷举命名变体**，直接转备用链路（判定与话术见 deliver.md A0）。

1. `navigate_page` 开 `https://mp.weixin.qq.com/` → `evaluate_script` 读 `location.href` 拿 token。
2. **未登录就一句话交接用户扫码**（自带浏览器里扫一次，后续复用），不写循环死等。
3. `navigate_page` 开 appmsg_edit（新建 `isNew=1`；修当期草稿 `appmsgid=<id>`）→ `wait_for` 正文占位符 → `take_snapshot` 关掉弹窗。
4. 填标题：`evaluate_script` 执行标题函数（`insertText`，标题串用 `JSON.stringify` 生成）。
5. 注入正文：`Read` `inject-fn.js` 全文 → `evaluate_script { function: <全文> }`，**一字不改**。
6. 保存：`take_snapshot` 取「保存为草稿」uid → `click` → `evaluate_script` 从 URL/`cgiData` 取 `appmsgid`。**取到空值但 URL 里已有 id → 从 URL 回填报告并记 `appmsgid_note`，不得判失败重跑注入（会新建草稿）。**
7. 复验：用 `appmsgid` 重开编辑器 → `evaluate_script` 计数（`h2 ≥ 2`、`chars > 800`、`pageHasTitle=true`）。
8. 写 `draft-report.json`；不达标用**同一 appmsgid** 回步骤 3 修，禁止新建草稿。
9. 封面图：可试一次 `upload_file`，失败立即转为交用户手动选 `images/00-cover.jpg`。

> ⚠️ 正文注入只能走 `body.html → build-inject（base64） → 页面内执行 inject-fn.js` 这条链。**严禁**把 HTML 手拼成 JS 字符串字面量注入——转义失败会被服务端清洗成正文只剩几十字的纯文本。`evaluate_script` 要的是函数声明，传 `inject.js`（IIFE）会报解析错。

**备用链路**：自带浏览器不可用（MCP 未挂载/未注册/被策略拦）时，才用 `scripts/wechat_draft.py`（Playwright + 本机 Chrome + 持久化 profile，扫码一次即复用），命令与环境自检项见 deliver.md 路径 B。两个已知时序坑（详见手册）：**卡在 `[1/6]` 而用户已扫码** → 登录循环只读首个 tab 的 URL，结束进程重跑即可（cookie 已存，勿让用户重扫）；**日志 `appmsgid=` 为空** → 从同行 url 回填。

## 反模式

- **编造或凭记忆写链接/数字/日期** —— 最严重，宁可少一条
- 未核实发布时间就把 D-1 的事写进「今日资讯」
- 用「今天/最新」等相对词检索，或沿用上一次会话的旧消息
- 只复述新闻，没有关系链、没有评论
- 评论写成股评/荐股/投资建议，或预测具体股价涨跌
- 观点没有事实支撑，为凑四维硬编
- 条目 20+ 摊薄，或每条都是三段长文（违背压缩）
- 交付 Markdown/纯文本，或用 class 代替 inline style
- 手拼 HTML 字符串注入正文；或注入失败后反复新建草稿而不修 `appmsgid`
- 给 `evaluate_script` 传 `inject.js`（IIFE）—— 自带浏览器要函数声明，必须传 `inject-fn.js`
- 在自带浏览器里写循环死等扫码 —— 一句话交接用户，等回复再继续
- 反复自动化上传封面图（封面槽需要真实手势，试一次不成即交用户）
- 未确认标题与评论口径就写入草稿
- 为凑往日块的海外占比塞旧闻——时区换算把 D-1 美东下午的事划进今日块后，占比缺口是正常的，记「已知偏差」即可
- 正文配额不够就删掉已核实候选——应降格写进观察卡，台账不能断
- 静默超 CJK 上限，或超了却不把豁免理由写进 `candidates.md`
- MCP 报 `tool not found` 就反复试命名变体、或据此断定浏览器面板坏了——整会话未注册时直接降级备用链路
- 备用脚本日志 `appmsgid=` 为空就当失败重跑注入（会新建草稿）；或在用户已扫码后还让人再扫一次

## 完成定义

**成功**：窗口已锚定并回显 → 候选表落盘且每条有链接与核实状态 → 每条完成三件套压缩 → 今日/往日分块正确且带日期徽标 → 条目短评 + 速递观察成文 → 正文 HTML+inline CSS 且 CJK 1500-2200（超上限已取得用户豁免并记录）→ 首屏今日主线行与性质声明/署名行齐全 → 封面图已用 ImageGen 实际生成并压成 jpg → `inject-fn.js` 由脚本生成 → 自带浏览器（或备用链路）写入并保存成功、appmsgid 已确定、同 appmsgid 重载复验达标 → `draft-report.json` 已落盘 → 已向用户汇报 appmsgid、原创开关与封面等待手动项。

**失败停止（如实汇报，不掩盖）**：核实不到发布日期/链接；复验两次仍不达标；自带浏览器不可用且备用脚本也跑不起来；用户未确认标题与评论口径。
