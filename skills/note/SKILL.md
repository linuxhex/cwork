# cwork-note — 个人工作台简报

## 概述

启动后输出**干净、紧凑的终端简报**：
1. 今日资讯（有则展示）
2. 今日待办（有则展示）
3. 知识库可用时静默使用，不必单独刷状态行
4. 安排 **17:30** 下班提醒：云效填写 + 工时满 8h

用户可在同一会话口述知识与待办，沉淀进本地知识库。

## 语言约束（强制）

- 所有对话、输出使用中文
- 仅保留路径、命令、字段名为英文

## HARD GATE

- 知识库默认只写用户明确要沉淀的内容；不要擅自改历史笔记结构
- 云效相关为**只读检查**，不替用户填写工时
- 查不到如实说，禁止臆造待办/需求/工时
- 提醒时间默认 17:30；用户改时间则以用户为准
- **没有内容的区块一律不展示**（不要写「暂无待办」「资讯暂不可用」「知识库不可用」这类空状态占位，除非用户明确追问状态）
- **待办必须以脚本结果为准**：先跑 `scripts/brief.sh`，禁止在脚本已列出待办后输出「还没有待办」

## 本地知识库

- Vault：`/Users/caomunian/Documents/Notes`
- 待办入口：`inbox.md`（`- [ ]` / `- [x]`）
- 目录：`待办/`、`认知/`
- MCP：Cute / Claude 已配置 `obsidian`。优先用 Obsidian MCP；不可用时回退读写 vault 文件。

## 输出格式（强制）

目标：一眼能扫完，像精致的终端 dashboard，不要大段说明、不要空区块。

### 排版规则

1. 用一个代码块输出整张简报（等宽对齐）
2. 标题一行：`今日简报 · YYYY-MM-DD HH:MM`
3. 分区用短横线分隔，左侧标签固定宽度对齐，例如 `待办` / `资讯` / `提醒`
4. **某区若无数据：整区省略**（含标题）
5. 待办只列未完成（`- [ ]`），最多 12 条；已完成默认不列
6. 资讯最多 4 条，每条一行，可带来源短标签；搜不到就整区省略，不要写「暂不可用」
7. 底部最多一行轻提示（例如「直接说待办/认知，我会写入知识库」）；若上面已很满可省略
8. 不要 emoji 刷屏；最多用 `·` `─` `☐` 这类符号
9. **不要输出 `# meta` 段**（那是脚本给自己看的）

### 有内容时的参考样式

```text
今日简报 · 2026-11-05 09:12
────────────────────────────────
资讯
  · Rust 1.84 stable 发布要点
  · 云效 OpenAPI 工时字段变更说明
────────────────────────────────
待办  3
  ☐ 补齐订单导出异步方案
  ☐ 回复设计评审意见
  ☐ 整理昨日会议结论到认知/
────────────────────────────────
提醒  17:30  云效填写 · 工时 8h
────────────────────────────────
直接说待办 / 认知，我会写入知识库
```

### 只有待办时

```text
今日简报 · 2026-11-05 09:12
────────────────────────────────
待办  2
  ☐ 补齐订单导出异步方案
  ☐ 回复设计评审意见
────────────────────────────────
提醒  17:30  云效填写 · 工时 8h
```

### 什么都没有时

只输出标题 + 提醒 + 一行引导，不要硬凑资讯/待办区：

```text
今日简报 · 2026-11-05 09:12
────────────────────────────────
提醒  17:30  云效填写 · 工时 8h
────────────────────────────────
还没有待办。直接告诉我今天要做什么。
```

## 执行步骤（强制顺序）

### 0) 先跑确定性简报脚本（必须）

技能目录下执行：

```bash
bash "${CWORK_NOTE_SKILL_DIR:-$HOME/.claude/skills/cwork-note}/scripts/brief.sh"
```

把 stdout 里的 dashboard 段（到提醒/引导行为止）作为简报骨架；**待办区以它为准**。`# meta` 之后的内容只给自己用，不要贴进用户可见简报。

若脚本失败，再回退读 `inbox.md`，但仍遵守「有待办必须展示」。

### 1) 知识库（静默补读，可跳过）

1. 优先 Obsidian MCP 读 `inbox.md` 与今日相关笔记（用于后续沉淀，不必单独刷状态）
2. 失败则直接用文件：
   ```bash
   test -d /Users/caomunian/Documents/Notes/.obsidian && echo OK
   cat /Users/caomunian/Documents/Notes/inbox.md
   ```
3. 不要单独输出「知识库状态」区块

### 2) 资讯（可选，失败就省略）

有高质量短讯才展示（可用 WebSearch）；失败、额度受限或无价值则**整区省略**，不要写「暂不可用」。不要为了资讯拖慢首屏——可以先出简报，再决定是否补资讯。

### 3) 合成最终简报

以 `brief.sh` 骨架为主：
- 有资讯 → 插到标题下方
- 待办/提醒保持脚本结果
- 不要把「还没有待办」和已存在的待办区同时输出

### 4) 下班提醒（查云效：需求/任务 + 工时满 8h）

- **不自动预约定时**：用户会主动说「下班检查」或「查工时」时再执行
- 用户触发时检查两件事（都只读）：
1. **云效需求/任务是否填写**
   - `bash "$HOME/.claude/skills/cwork-requirement/skills/requirement/scripts/yunxiao_query.sh" list`
   - 或本机 `/Users/caomunian/Study/cwork/skills/requirement/scripts/yunxiao_query.sh list`
2. **今日预计工时是否满 8 小时（只查莲子）**
   - `bash "$HOME/.claude/skills/cwork-note/scripts/yunxiao_worktime.sh"`
   - 不传日期默认今天；默认成员「莲子」
   - 口径是云效「预计工时」（`export_insight_expected_work_time`），不是登记工时
   - 输出 `total_hours` 与 `status=满8h/未满/无法检查(...)`，detail 行给出各工作项与小时数
   - 查不到如实说「无法检查（原因）」，**不编造小时数**

下班检查输出（同样省略空项）：

```text
下班检查 · 17:30
────────────────────────────────
云效  今日相关 2 项已更新 / 未填写 / 无法检查（原因）
工时  6.5 / 8h · 还差 1.5h / 满 8h / 无法检查（原因）
建议  把没填的补到云效
```

### 5) 会话内沉淀

- 待办 → `inbox.md` 的 `## 待办`（`- [ ] ...`）
  - 优先：`bash scripts/append_todo.sh "..."`
  - 或 Obsidian MCP 编辑 `inbox.md`
- 认知/知识 → `认知/` 下按日期或主题 md
- 写完用一两行确认路径，不刷屏

## 启动触发词

以下情况直接执行，不必再确认：
- `/cwork-note`、`cwork-note`、`今日简报`、`今日待办`、`下班提醒`
- Cute 启动会话的初始 prompt 要求执行本技能
