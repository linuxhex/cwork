# 页面自动化测试

## 概述

`cwork-test` 是 cwork 的测试技能，通过自然语言指令驱动页面自动化测试。在真实页面上执行操作并验证结果，无需编写测试代码。

### 核心流程

1. **环境准备**：启动开发服务器，注入页面自动化引擎
2. **测试规划**：根据需求分析/实现计划，生成测试场景
3. **测试执行**：按自然语言指令操作页面
4. **结果报告**：记录测试结果，发现问题自动修复并重测

### 在 cwork 流程中的位置

```
cwork-init → cwork-implement → cwork-test → cwork-commit
                                    ↑
                              本技能介入
```

- cwork-implement 完成后自动衔接
- 测试通过后进入 cwork-commit

## 语言约束（强制）

- **所有对话必须使用中文**
- **所有测试报告必须使用中文**
- 仅在必要处保留英文：命令、路径、选择器、代码

## 前置条件

### 必须满足

1. 存在前端工程（含 `package.json`）
2. 有可用的启动命令（`dev`/`start`/`serve`）
3. page-agent 已安装（`npm install page-agent`）或未安装时自动注入 CDN 版本

### page-agent 依赖

**page-agent** 是本技能的核心驱动引擎，通过自然语言指令操作浏览器页面。

- **NPM 安装（推荐）**：`npm install page-agent`，然后在代码中 `import { PageAgent } from 'page-agent'`
- **CDN 注入（快速测试）**：在浏览器控制台或通过脚本注入 `<script src="https://cdn.jsdelivr.net/npm/page-agent@1.12.2/dist/iife/page-agent.demo.js"></script>`
- **模型配置**：PageAgent 需要 LLM API 配置（model / baseURL / apiKey），用于理解自然语言指令并执行页面操作
- **语言设置**：`language: 'zh-CN'`，确保中文指令正确理解

### 自动检测

```bash
# 检测前端工程
if [ -f "package.json" ]; then
    # 检测启动命令
    if grep -q '"dev"' package.json; then
        DEV_CMD="npm run dev"
    elif grep -q '"start"' package.json; then
        DEV_CMD="npm start"
    elif grep -q '"serve"' package.json; then
        DEV_CMD="npm run serve"
    fi
fi
```

2. 等待服务就绪（轮询检测端口可用）
3. 记录服务地址（默认 `http://localhost:3000`，端口冲突时自动递增）

### 步骤 2：注入 page-agent

**方式 A：NPM 包（推荐，项目已安装）**

```javascript
import { PageAgent } from 'page-agent'
```

**方式 B：CDN 注入（快速测试）**

在浏览器控制台或通过脚本注入：

```html
<script src="https://cdn.jsdelivr.net/npm/page-agent@1.12.2/dist/iife/page-agent.demo.js"></script>
```

### 步骤 3：确认页面可访问

通过 page-agent 执行首次页面检查：

```
agent.execute("确认页面已正常加载，没有报错弹窗")
```

## 内部阶段三：测试执行

### 执行模式

**通过 page-agent 执行自然语言指令：**

```javascript
// 初始化 agent
const agent = new PageAgent({
    model: '当前使用的模型',
    baseURL: '模型 API 地址',
    apiKey: 'API Key',
    language: 'zh-CN',
})

// 执行测试步骤
await agent.execute('点击登录按钮')
await agent.execute('在用户名输入框中输入 "testuser"')
await agent.execute('在密码输入框中输入 "password123"')
await agent.execute('点击提交按钮')

// 验证结果
const result = await agent.execute('检查页面是否显示"欢迎"或用户头像')
```

### 执行流程

```
对于每个测试场景：
    1. 输出当前场景名称
    2. 按步骤执行 page-agent 指令
    3. 每步执行后检查结果
    4. 记录通过/失败
    5. 失败时截图记录当前状态
    6. 继续下一个场景
```

### 执行输出格式

```
═══════════════════════════════════════════════════════════════
【测试执行】场景 1/3：用户登录
═══════════════════════════════════════════════════════════════

步骤 1：打开 /login
  → page-agent: "导航到登录页面"
  → 结果：✓ 页面加载成功

步骤 2：输入用户名
  → page-agent: "在用户名输入框输入 testuser"
  → 结果：✓ 输入成功

步骤 3：输入密码
  → page-agent: "在密码输入框输入 password123"
  → 结果：✓ 输入成功

步骤 4：点击登录
  → page-agent: "点击登录按钮"
  → 结果：✓ 按钮点击成功

步骤 5：验证跳转
  → page-agent: "检查当前页面是否包含'欢迎'文字或用户头像"
  → 结果：✓ 验证通过

场景 1 结果：✓ 通过（5/5 步骤）
```

### 失败处理

```
步骤 4：点击登录
  → page-agent: "点击登录按钮"
  → 结果：✗ 按钮未找到

  诊断：
  → 页面当前 URL：/login
  → 页面可见按钮：["注册", "忘记密码"]
  → 可能原因：登录按钮文字与预期不符

  处理：
  → 尝试替代指令："点击包含'登录'文字的按钮"
  → 重试结果：✓ 找到并点击成功
```

## 内部阶段四：结果报告

### 报告格式

测试结果记录到 `docs/requirements/{requirement_key}/test-report.md`：

```markdown
# 测试报告

## 概要
- 测试时间：2026-07-24 15:30:00
- 测试环境：http://localhost:3000
- 场景总数：3
- 通过：2
- 失败：1
- 通过率：66.7%

## 详细结果

### 场景 1：用户登录 ✓
| 步骤 | 操作 | 结果 |
|------|------|------|
| 1 | 打开 /login | ✓ |
| 2 | 输入用户名 | ✓ |
| 3 | 输入密码 | ✓ |
| 4 | 点击登录 | ✓ |
| 5 | 验证跳转 | ✓ |

### 场景 2：数据列表展示 ✓
| 步骤 | 操作 | 结果 |
|------|------|------|
| 1 | 打开 /dashboard | ✓ |
| 2 | 验证列表加载 | ✓ |
| 3 | 验证分页 | ✓ |

### 场景 3：表单提交 ✗
| 步骤 | 操作 | 结果 | 备注 |
|------|------|------|------|
| 1 | 打开 /form | ✓ | |
| 2 | 填写必填字段 | ✓ | |
| 3 | 提交表单 | ✗ | 提交按钮无响应 |
| 4 | 验证成功提示 | - | 未执行 |

## 失败分析

### 场景 3：表单提交
- 失败步骤：步骤 3 — 提交表单
- 现象：点击提交按钮后页面无变化
- 可能原因：表单验证未通过，必填字段遗漏
- 建议：检查表单验证逻辑

## 修复建议
1. [场景3] 检查表单提交按钮的事件绑定
2. [场景3] 确认所有必填字段的校验规则
```

### 自动修复循环

测试失败时，尝试自动修复：

```
if 测试失败:
    1. 分析失败原因（通过 page-agent 检查页面状态）
    2. 定位代码问题
    3. 修复代码
    4. 等待热更新
    5. 重新执行失败的场景
    6. 最多重试 3 次
    7. 仍失败则记录到报告，等待人工处理
```

## HARD GATE

- 环境未就绪（服务未启动），禁止执行测试
- 测试规划未经用户确认，禁止执行
- 所有 P0 场景必须通过才能进入 cwork-commit
- P1/P2 场景失败可记录但不阻塞提交

## 与 cwork-implement 的衔接

cwork-implement 完成后：

1. 自动检测是否有前端工程改动
2. 有前端改动 → 自动进入 cwork-test
3. 无前端改动 → 跳过，直接进入 cwork-commit

```
═══════════════════════════════════════════════════════════════
【自动衔接】检测到前端改动，进入 cwork-test
═══════════════════════════════════════════════════════════════
```
