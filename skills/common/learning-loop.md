# cwork 自改进机制规范

## 概述

cwork 自改进系统从 Hermes Agent 的学习循环理念吸收，适配 cwork 的技能内容层架构。核心思想：**任务结束自动提议改进，知识结构化沉淀，模式可检索复用**。

**设计原则**：
1. **最小摩擦** — 不打断工作流，任务结束时顺带自检
2. **高信号** — 只捕获有价值的改进，不记流水账
3. **结构化** — 知识入模式库，不堆 USAGE_NOTES
4. **可追溯** — 技能变更有 CHANGELOG，版本可查

## 学习触发层（When to Learn）

### 触发时机

| 触发点 | 触发条件 | 学习类型 |
|--------|---------|---------|
| 任务完成 | implement/bug/do 收敛后 | 技能改进提议 |
| 踩坑时刻 | 遇到 known-pits 未记录的问题 | 模式库更新 |
| 重复动作 | 同一件事做了 ≥3 次 | 抽象建议 |
| 用户纠正 | 用户说「不对」「错了」 | 行为修正 |
| 每日首次 | `.last_analysis_date` ≠ 今天 | 跨会话扫描 |

### 任务完成自检清单（implement/bug/do 结束时必做）

回顾本次任务，回答以下问题：

1. **已知坑命中检查**
   - 本次是否踩到 known-pits 里的问题？
   - 命中但 known-pits 没记录 → 提议补充
   - 命中且记录准确 → 无需改动

2. **重复动作检测**
   - 本次有没有重复做某件事（≥3 次）？
   - 有 → 提议抽象成脚本/模板/快捷命令

3. **文档偏差检查**
   - 技能文档有没有与实际不符的地方？
   - 有 → 提议修正文档或修正实现

4. **新反模式发现**
   - 本次有没有发现新的错误做法？
   - 有 → 提议加入 HARD GATE 或反模式清单

### 输出格式

```markdown
## 技能改进提议（本次任务发现）

- [skill-name] 提议内容（原因：本次 xxx）
- [skill-name] 提议内容（原因：本次 xxx）
- ...

是否立即改进？[Y/n/记入待分析]
```

## 知识提取层（What to Capture）

### 知识类型

| 类型 | 来源 | 存储位置 | 格式 |
|------|------|---------|------|
| 踩坑记录 | 任务中遇到的问题 | `pattern-library.md` | 问题 + 根因 + 解法 |
| 重复动作 | 做了 ≥3 次的事 | `pattern-library.md` | 动作 + 抽象建议 |
| 用户偏好 | 用户的纠正/选择 | `memory/user-preferences.md` | 偏好维度 + 值 |
| 技能偏差 | 文档与实际不符 | `pattern-library.md` | 技能 + 偏差描述 |
| 新反模式 | 错误做法 | `pattern-library.md` | 反模式 + 正确做法 |

### 踩坑记录格式

```markdown
### [YYYY-MM-DD] [skill-name] 问题简述

**现象**：具体表现
**根因**：为什么会这样
**解法**：怎么解决的
**可借鉴**：一句话总结教训
**关联模式**：[[模式名]]（如果有）
```

### 重复动作检测规则

当发现同一类动作在本次任务中出现 ≥3 次时：
1. 记录动作模式
2. 提议抽象成脚本/模板
3. 如果用户同意，创建脚本并记入 `pattern-library.md`

### 用户偏好提取规则

当用户纠正 agent 行为时：
1. 记录纠正内容
2. 判断是否为偏好（vs 一次性要求）
3. 如果是偏好，更新 `memory/user-preferences.md`

## 模式识别层（Pattern Recognition）

### 模式库位置

`skills/common/pattern-library.md` — 从实战中提取的可复用模式/反模式。

### 模式匹配规则

遇到新问题时：
1. 提取关键字（技能名 + 现象词）
2. 在模式库中搜索相似模式
3. 如果命中：
   - 检查解法是否适用
   - 适用 → 直接应用，记入本次任务日志
   - 不适用 → 创建新模式或修正现有模式
4. 如果未命中：
   - 解决问题后提取新模式
   - 提议加入模式库

## 记忆检索层（Memory & Retrieval）

### 会话索引位置

`skills/common/session-index.md` — 历史任务的结构化索引。

### 检索触发条件

遇到以下情况时自动检索会话索引：
1. 踩到 known-pits 未记录的问题
2. 同一类问题第二次出现
3. 用户说「之前遇到过」

### 检索输出格式

```
[历史参考] YYYY-MM-DD 遇到过类似问题：
- 任务类型：xxx
- 根因：yyy
- 解法：zzz
- 会话详情：session-index.md#日期-任务名
```

## 与现有机制的整合

| 现有机制 | 整合方式 |
|---------|---------|
| USAGE_NOTES.md | 保留，作为「待分析」暂存区；分析后入模式库或会话索引 |
| feedback-loop.md | 保留，每日分析时扫描模式库更新需求 |
| known-pits | 迁入模式库的反模式区，保持引用兼容 |
| memory/ | 保留，扩展用户偏好维度 |

## 技能演化追踪

### 变更日志

每个技能维护 `CHANGELOG.md`（自动追加），格式：

```markdown
# [skill-name] 变更日志

## [YYYY-MM-DD] 变更简述

**触发**：为什么改
**改动**：改了什么
**影响**：有什么效果
```

### 版本号规则

版本 = 最后一次实质性改动的 commit hash 前 7 位。

技能文件头部加版本标记：
```yaml
---
name: cwork-implement
version: ade2911
---
```
