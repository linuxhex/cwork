> 从实战中提取的可复用模式/反模式。每次任务结束自检时查阅。
> 参考 `common/learning-loop.md` 的完整规范。

---

## 反模式（HARD GATE 来源）

### [P001] 空壳输出
- **现象**：查询/分析结果只有一句话
- **根因**：阶段 3 没有硬门禁
- **解法**：各技能加必填字段自检
- **关联技能**：log/data/config/graf/deploy
- **来源**：USAGE_NOTES 2026-11-05

### [P002] 盲试选择器
- **现象**：测试时反复换选择器尝试
- **根因**：没有先 snapshot 看真实 DOM
- **解法**：known-pits 强制先 snapshot 再写选择器
- **关联技能**：test
- **来源**：USAGE_NOTES 2026-11-02

### [P003] 并发更新数据不一致
- **现象**：多线程/多实例同时更新同一数据，结果不一致
- **根因**：未加锁或锁粒度不对
- **解法**：加分布式锁或数据库行锁
- **关联技能**：bug/implement
- **来源**：待补充

## 可复用模式

### [M001] 多服务早期识别
- **触发**：需求分析阶段发现跨服务调用
- **动作**：立即切换多服务模式，为每个服务建独立文档
- **关联技能**：implement
- **来源**：implement SKILL.md

### [M002] 收敛双证据
- **触发**：cwork-do 每轮迭代结束
- **动作**：同时收集实测证据 + 理论推演
- **关联技能**：do/implement/bug
- **来源**：do SKILL.md

### [M003] 任务结束自检
- **触发**：implement/bug/do 任务完成时
- **动作**：执行 4 项自检（已知坑/重复动作/文档偏差/新反模式），输出改进提议
- **关联技能**：implement/bug/do
- **来源**：learning-loop.md（2026-11-09 新增）

## 模式匹配规则

遇到新问题时：
1. 提取关键字（技能名 + 现象词）
2. 在本文件中搜索相似模式
3. 如果命中：
   - 检查解法是否适用
   - 适用 → 直接应用，记入本次任务日志
   - 不适用 → 创建新模式或修正现有模式
4. 如果未命中：
   - 解决问题后提取新模式
   - 提议加入本文件
